## Critical Issues (Fix Immediately)

### 🔴 Issue #1: Undefined Variable in Exception Handlers
**Location:** `backend/server.js:1632, 1641, 1660`
**Severity:** CRITICAL
**Type:** ReferenceError

**Problem:**
```javascript
catch (_err) {
  logger.error('Error checking bridge status:', err);  // ❌ 'err' is undefined
}
```

The catch block uses `_err` parameter but references `err` in the error handler, causing `ReferenceError: err is not defined`.

**Impact:** Error handling fails completely, causing cascading failures and preventing proper debugging.

**Fix:**
```javascript
catch (_err) {
  logger.error('Error checking bridge status:', _err);  // ✅ Use correct variable
}
```

**Files to fix:**
- Line 1632: Bridge status check
- Line 1641: Version read error
- Line 1660: Database health error

### 🔴 Issue #2: Unhandled Promise Rejection
**Location:** `backend/server.js:1917-1921`
**Severity:** CRITICAL
**Type:** Unhandled Promise

**Problem:**
```javascript
SyncService.checkRsyncInstalled().then(result => {
  if (!result.installed) {
    logger.warn('rsync not installed...');
  }
});
// ❌ No .catch() handler
```

**Impact:** If promise rejects, triggers unhandled rejection that could crash the Node.js process.

**Fix:**
```javascript
SyncService.checkRsyncInstalled()
  .then(result => {
    if (!result.installed) {
      logger.warn('rsync not installed...');
    }
  })
  .catch(error => {
    logger.error('Failed to check rsync installation:', error);
  });
```

## High Severity Issues

### 🟠 Issue #3: Race Condition in Async setInterval
**Location:** `backend/server.js:455-484`
**Severity:** HIGH
**Type:** Race Condition

**Problem:** The snapshot cleanup runs in setInterval with async operations. If cleanup takes longer than 24 hours, multiple instances could run concurrently.

**Impact:** File access conflicts, double-deletions, data corruption.

**Fix:**
```javascript
let isCleanupRunning = false;
const snapshotCleanupInterval = setInterval(async () => {
  if (isCleanupRunning) return;
  isCleanupRunning = true;
  try {
    // ... cleanup logic
  } finally {
    isCleanupRunning = false;
  }
}, SNAPSHOT_CLEANUP_INTERVAL_MS);
```

### 🟠 Issue #4: Database Reference Mismatch (The Original Bug!)
**Location:** `backend/server.js:1928-1945`
**Severity:** HIGH
**Type:** Synchronization Bug

**Problem:** Both `MetricsCollector` and `healthCheckSystem` use `firstDb`, but Map iteration order isn't guaranteed to be stable. This is what caused your metrics collection error!

```javascript
const firstDb = projectDatabases.values().next().value;  // ❌ Unstable reference

metricsCollector = new MetricsCollector(firstDb, SESSION_ID, io);
healthCheckSystem = createDefaultHealthChecks(firstDb, io);
```

**Impact:** Health checks read from different database than metrics collector writes to, causing false positives.

**Fix:**
```javascript
// Use a deterministic database reference
function getMetricsDatabase() {
  // Always use 'raven' database if exists, otherwise first alphabetically
  const ravenDb = projectDatabases.get('raven');
  if (ravenDb) return ravenDb;

  // Get first database alphabetically (deterministic)
  const sortedProjects = Array.from(projectDatabases.keys()).sort();
  return sortedProjects.length > 0 ? projectDatabases.get(sortedProjects[0]) : null;
}

const metricsDb = getMetricsDatabase();
if (metricsDb) {
  metricsCollector = new MetricsCollector(metricsDb, SESSION_ID, io);
  healthCheckSystem = createDefaultHealthChecks(metricsDb, io);
}
```
